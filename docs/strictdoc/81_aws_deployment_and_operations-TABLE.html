        TARGET EC2 Start Sequence
        For an authenticated start request while the managed instance is stopped, the controller shall:

        1. resolve the requested runtime profile or use Profile 1 by default;
        2. resolve and constrain the requested idle timeout or use 20 minutes by default;
        3. modify the stopped instance to the selected approved EC2 type when necessary;
        4. persist the effective runtime-control state;
        5. initialize the run's last-activity time so an accidentally started but unused instance remains protected by the idle policy;
        6. issue StartInstances; and
        7. verify GHOST readiness before reporting the start operation as ready.

        GHOST-AWS-TGT-EC2-CONTROL-ACCEPTANCE
        TARGET EC2 Runtime-Control Acceptance
        The runtime-control target shall not be promoted to CURRENT until acceptance demonstrates at least that:

        1. the controller remains reachable while the GHOST EC2 instance is stopped;
        2. unauthenticated control requests are rejected;
        3. start with omitted options uses Profile 1 t3.medium and a 20-minute idle timeout;
        4. Profile 2 starts the same stopped instance as m7i-flex.xlarge;
        5. the effective idle timeout cannot be configured below 10 or above 120 minutes;
        6. the start operation reports ready only after the GHOST health check succeeds;
        7. status reports the actual EC2 state without refreshing idle activity;
        8. explicit stop stops but does not terminate the instance;
        9. health checks, polling, and background host activity do not keep the instance alive;
        10. qualifying authenticated GHOST MCP tool calls refresh the inactivity timer;
        11. the serverless watchdog stops an idle instance; and
        12. the EC2-local watchdog independently stops an idle instance when the Lambda watchdog path is unavailable.
