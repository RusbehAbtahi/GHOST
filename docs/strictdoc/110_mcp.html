    1. 1. Purpose and Scope

    STATEMENT: This document defines the parent requirements for the GHOST Model Context Protocol capability.

    MCP is a first-class GHOST interface family. It is not part of the graphical/human-interface requirement family.

    This document owns the common MCP contract shared by all GHOST MCP capabilities:
    - protocol and transport;
    - client interoperability;
    - authentication and authorization;
    - authenticated owner identity;
    - tool discovery and invocation;
    - request isolation;
    - rate limiting;
    - common error and security behavior;
    - deployment ownership boundaries; and
    - capability-extension governance.

    Detailed functional behavior is owned by the MCP child requirement files:

    - 111_mcp_capabilities.sdoc:
    Prompt Engineering, Episodic Memory, Clipboard Memory, and Collection Memory.

    - 112_mcp_activeblackboard.sdoc:
    all current and future ActiveBlackboard behavior, including the current Persistent Chat prototype.

    - 113_mcp_runtime_control.sdoc:
    MCP-visible GHOST runtime lifecycle control, including remote start, stop, status, readiness, and selectable EC2 runtime profile.

    Runtime, container, local-hosting, AWS, reverse-proxy, HTTPS, Cognito, and deployment realization remain owned by the Runtime Platform and Operations requirement family.

    2. 2. MCP Communication Contract

    GHOST-MCP-REMOTE-TOOL-PROVIDER
    2.1. MCP Tool Provider Role
    UID: GHOST-MCP-REMOTE-TOOL-PROVIDER
    STATUS: Draft
    RELATIONS (Parent):
    • GHOST-MCP-ROOT GHOST MCP Capability Scope
    STATEMENT: The GHOST MCP server shall act as a tool provider.

    An external AI client shall explicitly invoke an exposed GHOST MCP operation.

    The MCP server shall not claim to passively receive, monitor, intercept, or persist ordinary client conversation traffic for which no applicable GHOST tool invocation occurs.

    UID: GHOST-MCP-OWNER-ISOLATION

    4. 4. Shared Runtime and Safety Behavior

    STATUS: Draft
    RELATIONS (Parent):

    4.4. Error Information Sanitization

    STATUS: Draft

    7. 7. Controlled Extension and Requirement Stability

    STATEMENT: The former 73_mcp_interface.sdoc described an earlier, prompt-engineering-only MCP scope.

    Requirements from that document whose engineering meaning remains valid retain their established GHOST-MCP requirement UIDs in this new MCP family.

    Obsolete single-tool exclusions are not reused for a different meaning.

    New MCP functionality receives new UIDs rather than silently redefining unrelated existing requirements.
